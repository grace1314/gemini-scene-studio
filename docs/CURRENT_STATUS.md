# 当前状态与工程审计

审计日期：2026-10-28。项目定位是 Gemini 305 双目、20 帧以内、小场景/桌面物体的离线米制重建与几何约束 Gaussian Splatting 研究工作台。

## 已经闭环的主流程

当前默认链路已经从采集跑通到训练：

```text
Gemini 305 无损双目 PNG
  → BridgeDepth 全分辨率米制深度
  → 每帧多边形 ROI + 深度范围
  → 左目 RGB 的 ALIKED + LightGlue
  → COLMAP 增量 SfM + 全局 BA
  → BridgeDepth 恢复一个全局米制尺度
  → 掩膜 RGB-D 点云融合
  → Open3D Scalable TSDF 网格
  → gsplat 3DGS + 新视角与 Splat 导出
```

已完成的关键修正包括：预览压缩而采集保留原图、正式深度恢复到 1280×800、ROI 逐帧保存、COLMAP 全图像对匹配与 BA、米制尺度恢复、点云/TSDF 依赖检查、训练 CUDA 环境修复、真实 Splat 查看器自动以 Gaussian 质心聚焦。

OmniVGGT、SIFT+RGB-D PnP 和 ICP 不再是默认位姿分支。它们的历史代码/产物尚未删除，便于复盘，但不应再被页面文案描述成当前主流程。

## 当前场景的实测结果

用于开发验收的私有场景共 20 帧，正式处理分辨率 1280×800，当前有效运行链如下；仓库内公开示例已另行脱敏并重新验证。

| 阶段 | 结果 |
|---|---|
| 深度 | 20 帧全分辨率；峰值显存约 2.34 GiB |
| COLMAP | 20/20 注册，1692 个稀疏点，平均重投影误差 1.07 px |
| 尺度 | 6267 个样本、5379 个内点，全局尺度 0.06156 |
| 点云 | 146,038 点，2 mm 体素 |
| TSDF | 34,042 顶点、65,840 三角形，3 mm 体素、12 mm 截断 |
| 3DGS | 80,000 Gaussians、3000 步、86.5 秒、峰值显存约 211 MiB |

需要正确解读训练数字：当前训练集平均 PSNR 只有 **8.17 dB**，这已经明确说明外观拟合不足；最终 `dense_match=0` 表明所谓稠密匹配约束在训练结束时没有产生有效贡献。57 张“新视角”只是相邻已知位姿间插值，不是留出视角的客观质量证明。

当前还有两帧 `0006`、`0007` 没有多边形 ROI。它们会按全画面参与后续筛选，容易把背景和错误深度带入点云及训练。

## 优点

- 数据不原地修改：帧、运行请求、日志和产物可追溯。
- 位姿主干已经合理：全分辨率 RGB 特征、COLMAP SfM/BA、深度只负责米制尺度，而不是用噪声深度强行初始化位姿。
- 点云和 TSDF 共用同一条优化轨迹，便于比较几何误差。
- 8 GB 显存足以分阶段运行；当前实测峰值远未触顶。
- 网页已经覆盖采集、ROI、任务状态、产物下载和交互查看。

## 主要缺点

### 数据与几何

- 双目标定仍是整体上限；当前没有每次采集前的标定质量门禁。
- 单一全局深度尺度不能修正 BridgeDepth 随位置/距离变化的系统误差。
- ROI 未覆盖全部帧，也没有前景 alpha/软边界，硬多边形会造成轮廓污染。
- TSDF 只导出表面网格，没有持久化体素 TSDF/SDF、权重和梯度，因此无法直接成为可微几何监督。
- 没有深度置信度、遮挡和动态区域的统一权重模型。

### 3DGS

- 网页当前提交的是快速基线：SH0、固定 80k Gaussian、无增密/拆分/剪枝、无 SSIM。
- `training_quality.py` 已有实验性的 SH/SSIM/自适应密度代码，但页面没有启用，也未通过当前真实场景的质量验收。
- Farneback 光流生成的稠密对约束不够可靠，且最终损失为 0；它不能代表几何约束已经生效。
- 表面项只锚定初始化点，不能持续约束渲染表面法线、局部平面或 SDF 零水平面。
- 相机位姿固定；COLMAP 轨迹仍有小误差时，3DGS 只能用变大/变糊的 Gaussian 吸收误差。
- 只有训练视角 PSNR，没有留出视角 PSNR/SSIM/LPIPS，也没有深度、法线或 Chamfer 指标。

### 工程

- `runs/` 混合了正式结果、失败日志和旧算法实验；当前场景约 1.7 GiB，其中约 1.2 GiB 不属于当前有效链。
- `web/app.js` 是单文件并存在后定义覆盖前定义的演进痕迹，维护成本较高。
- worker 仍保留退役后端入口，页面和旧文档中也存在少量过时文案。
- 源码目录包含约 799 MiB 第三方资源和约 124 MiB 构建产物；它们已被 Git 忽略，但备份/迁移时应分层处理。

## 优先优化顺序

1. 补齐 20/20 ROI，并建立 2–4 帧留出视角；没有验收集就不能判断 3DGS 是否变好。
2. 页面区分“快速预览”和“质量训练”，先把现有质量训练器以受控参数接入。
3. 用 LightGlue/COLMAP tracks 与深度构建可靠的跨视角 3D 对应，替换 Farneback 约束。
4. 加入 edge-aware 深度、渲染法线与 TSDF/表面约束，再考虑小幅位姿联合优化。
5. 若 3DGS 的几何仍不稳定，再增加独立 2DGS/PGSR 后端，而不是继续堆叠固定椭球。

详细实验配置见 [3DGS_ROADMAP.md](3DGS_ROADMAP.md)。
